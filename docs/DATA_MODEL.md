# Формат данных

Всё хранится в одном файле `files/kopeechka.json` во внутреннем хранилище приложения.
Этот же файл целиком уходит в резервную копию на Google Диск, поэтому формат копии
и формат хранения — одно и то же.

## Верхний уровень

```json
{
  "version": 1,
  "accounts": [...],
  "categories": [...],
  "txs": [...],
  "goals": [...],
  "settings": { ... },
  "nextId": 1042
}
```

`nextId` — счётчик для идентификаторов операций, счетов, категорий и целей.

## Счёт (`accounts`)

```json
{
  "id": "card",
  "name": "Карта · 4417",
  "type": "Карта",
  "mask": "•• 4417",
  "cur": "RUB",
  "initial": 98450.0,
  "inTotal": true
}
```

`initial` — стартовый остаток, а не текущий баланс: баланс считается из операций
(см. [ARCHITECTURE.md](ARCHITECTURE.md)). `inTotal` — учитывать ли счёт в сумме на главном экране.

## Категория (`categories`)

```json
{
  "id": "food",
  "code": "ПР",
  "name": "Продукты",
  "limitRub": 24000.0,
  "income": false,
  "color": "#4F7A5B"
}
```

`limitRub` — историческое имя ключа в JSON; значение хранится в основной валюте
пользователя (см. «Совместимость»).
`code` — две буквы в квадратике рядом с операцией. Пустой `color` означает «подобрать
автоматически» по позиции в списке.

## Операция (`txs`)

```json
{
  "id": 17,
  "date": 20710,
  "title": "Пятёрочка",
  "cat": "food",
  "acc": "card",
  "amount": -1840.0,
  "note": "",
  "toAcc": null,
  "toAmount": null,
  "goal": null
}
```

- `date` — номер дня по `LocalDate.toEpochDay()` (не миллисекунды: время суток не хранится).
- `amount` — в валюте счёта `acc`; отрицательная сумма это расход.
- Перевод: `cat` равен `"transfer"`, заполнены `toAcc` и `toAmount` (сколько зачислено
  в валюте счёта-получателя).
- Взнос на цель: `cat` равен `"goal"`, заполнено `goal` с идентификатором цели.

## Цель (`goals`)

```json
{
  "id": "g1",
  "name": "Отпуск в Грузии",
  "target": 180000.0,
  "saved": 68000.0,
  "cur": "RUB",
  "hint": "Хочу поехать в мае"
}
```

## Бизнес: прайс, клиенты, заказы

Появляются, когда включён модуль «Бизнес» (`settings.business`). У выключенного модуля
списки пустые, и старые копии открываются как есть.

```json
{
  "products": [
    {"id": "p1", "name": "Торт на заказ", "price": 171.0, "cost": 68.5, "unit": "шт", "archived": false}
  ],
  "customers": [
    {"id": "cl1", "name": "Айна", "contact": "Телефон", "note": ""}
  ],
  "orders": [
    {
      "id": 600, "no": "2026-008", "customerId": "cl1", "date": 20710, "due": null,
      "items": [{"productId": "p2", "name": "Капкейки, 12 шт", "qty": 1.0, "price": 83.9, "cost": 34.3}],
      "discount": 0.0, "extraCost": 0.0, "cur": "TMT", "status": "paid",
      "incomeTxId": 1001, "costTxId": null, "note": ""
    }
  ]
}
```

- `price` и `cost` в прайсе — **в основной валюте**, как лимиты категорий: при смене
  основной валюты они пересчитываются.
- В позиции заказа цена и затраты зафиксированы в **валюте заказа** (`cur`) на момент
  заказа: последующая правка прайса или курса их не трогает.
- `status` — строка: `new`, `work`, `done`, `paid`, `cancelled`. Незнакомое значение
  не ломает чтение — оно просто показывается как «новый».
- `incomeTxId` — операция дохода, созданная оплатой (категория `sale`); `costTxId` —
  операция расхода, если затраты списывали со счёта (категория `cost`). Удаление
  операции снимает с заказа отметку об оплате, удаление заказа удаляет его операции.
- Сумма заказа = Σ `qty × price` − `discount`; затраты = Σ `qty × cost` + `extraCost`.

## Настройки (`settings`)

| Поле | Что означает |
| --- | --- |
| `mainCur` | основная валюта: в ней считаются баланс, бюджеты и отчёты |
| `dark` | тёмная тема |
| `rates` | курсы: сколько рублей стоит единица валюты, `{"USD": 92.0}` |
| `currencyCodes` | включённые валюты |
| `customCurrencies` | валюты, заведённые вручную: код, символ, название |
| `onboarded` | пройдена ли заставка первого запуска |
| `userName` | как обращаться к пользователю на главном экране |
| `remind`, `remindHour` | вечернее напоминание и час |
| `showKopecks` | показывать копейки в суммах |
| `allowNegative` | разрешить уводить счета в минус (без этого расход больше остатка не запишется) |
| `business` | включён ли раздел «Бизнес» |
| `autoBackup`, `lastBackupAt`, `driveLinked` | состояние резервного копирования |
| `aiProvider`, `aiModels`, `customEndpoint`, `aiSets` | настройки ИИ-советника |

**API-ключей здесь нет.** Они лежат в отдельном хранилище, зашифрованные ключом из
Android Keystore (`SecureStore`), и не попадают ни в файл данных, ни в резервную копию.

## Обмен через CSV

Файл с колонками:

```
date;type;amount;currency;account;to_account;to_amount;category;note
2026-09-14;expense;-1200;TMT;Kart · 4417;;;Azyk;Bazar
2026-09-14;income;4500;TMT;Kart · 4417;;;Aýlyk;
2026-09-14;transfer;-500;TMT;Kart · 4417;Nagt pul;500;;
```

- `type` — `expense`, `income` или `transfer`. Взносы на цели выгружаются как `goal`
  и при загрузке пропускаются: ими управляет сама цель. Сколько строк пропущено,
  видно в предпросмотре.

Заказы выгружаются отдельным файлом с колонками
`no;date;customer;status;currency;total;cost;profit;items;note`; загрузки для них нет.
- Разделитель — точка с запятой или запятая (определяется по первой строке),
  кодировка UTF-8 с BOM, чтобы Excel открывал файл без плясок.
- Дата понимается в виде `2026-09-14`, `14.09.2026` или `14/09/2026`.
- Сумма расхода может быть и отрицательной, и положительной — знак ставится по типу строки.
- `to_amount` нужен только для переводов между разными валютами; если он пуст, сумма
  пересчитается по текущему курсу.
- Счета и категории ищутся по названию без учёта регистра. Чего нет — создаётся:
  счёт с нулевым остатком и валютой из строки, категория с автоматическим цветом.

Перед загрузкой приложение показывает, сколько строк подходит, сколько с ошибками
и что будет создано; сами данные меняются только после подтверждения.

## Совместимость

Чтение включает `ignoreUnknownKeys`, а все новые поля добавляются со значением по
умолчанию. Поэтому:

- копия, снятая старой версией, открывается новой — недостающие поля получают значения
  по умолчанию (так, например, добавились цвета категорий и список валют);
- копия из новой версии открывается старой — незнакомые поля просто игнорируются.

`version` отмечает формат: **1** — курсы и лимиты в рублях, **2** — в долларах,
**3** — в основной валюте пользователя (`settings.mainCur`), её собственный курс всегда 1.
Файл версии 1 или 2 (в том числе старая копия с Google Диска) переводится в версию 3 при
загрузке: все курсы делятся на прежний курс основной валюты, лимиты категорий пересчитываются
так же, а результат сразу сохраняется. Суммы операций и остатки счетов хранятся в валютах
самих счетов и не затрагиваются.

Смена основной валюты в настройках делает ровно тот же пересчёт: база переезжает на новую
валюту, относительные курсы сохраняются.

## Резервная копия

Файл в Google Диске называется `kopeechka-ГГГГ-ММ-ДД_ЧЧ-ММ-СС.json` и лежит в папке
«Копеечка — резервные копии». Хранятся 10 последних, старые удаляются автоматически.
Перед восстановлением текущее состояние сохраняется на телефоне в `files/before-restore.json`.
