# Формат данных

Всё хранится в одном файле `files/kopeechka.json` во внутреннем хранилище приложения
(на iOS — в папке документов приложения). Этот же JSON уходит в резервную копию,
поэтому формат копии и формат хранения — одно и то же (за вычетом того, что живёт
только на телефоне, — см. «Резервная копия»).

## Верхний уровень

```json
{
  "version": 3,
  "accounts": [...], "categories": [...], "txs": [...], "goals": [...],
  "debts": [...], "products": [...], "customers": [...], "orders": [...],
  "recurring": [...], "requests": [...],
  "space": { ... }, "deleted": { "tx:17": 1758180000000 },
  "smsSources": [...], "pushApps": { ... }, "merchantCats": { ... }, "inbox": [...],
  "settings": { ... },
  "nextId": 1042
}
```

`nextId` — счётчик идентификаторов. В общем бюджете у каждого участника свой диапазон
(`Sync.slotStart`), поэтому номера двух телефонов не пересекаются.

У всех записей, которые сливаются в общем бюджете, есть `changedAt` — время последней
правки в миллисекундах. Его ставит само хранилище при каждом изменении (`Sync.stamp`).

## Счёт (`accounts`)

```json
{
  "id": "card",
  "name": "Карта · 4417",
  "type": "Карта",
  "mask": "•• 4417",
  "cur": "RUB",
  "initial": 98450.0,
  "inTotal": true,
  "shared": false,
  "approveFrom": 0.0,
  "changedAt": 1758180000000
}
```

`initial` — стартовый остаток, а не текущий баланс: баланс считается из операций
(см. [ARCHITECTURE.md](ARCHITECTURE.md)). `inTotal` — учитывать ли счёт в сумме на главном экране.
`shared` и `approveFrom` — общий счёт и сумма, начиная с которой трата ждёт одобрения
второго участника (см. [SYNC.md](SYNC.md)).

**Золото** — счёт в «валюте» `XAU`: остаток в граммах, а курс `XAU` в настройках — цена
одного грамма в основной валюте.

## Категория (`categories`)

```json
{
  "id": "food",
  "code": "ПР",
  "name": "Продукты",
  "limitRub": 24000.0,
  "income": false,
  "color": "#4F7A5B"
}
```

`limitRub` — историческое имя ключа в JSON; значение хранится в основной валюте
пользователя (см. «Совместимость»).
`code` — две буквы в квадратике рядом с операцией. Пустой `color` означает «подобрать
автоматически» по позиции в списке.

## Операция (`txs`)

```json
{
  "id": 17,
  "date": 20710,
  "title": "Пятёрочка",
  "cat": "food",
  "acc": "card",
  "amount": -1840.0,
  "note": "",
  "toAcc": null,
  "toAmount": null,
  "goal": null,
  "by": "m-4f1c",
  "changedAt": 1758180000000
}
```

- `date` — номер дня по `LocalDate.toEpochDay()` (не миллисекунды: время суток не хранится).
- `amount` — в валюте счёта `acc`; отрицательная сумма это расход.
- Перевод: `cat` равен `"transfer"`, заполнены `toAcc` и `toAmount` (сколько зачислено
  в валюте счёта-получателя).
- Взнос на цель: `cat` равен `"goal"`, заполнено `goal` с идентификатором цели.
- `by` — участник общего бюджета, записавший операцию (пусто, пока бюджет личный).

## Цель (`goals`)

```json
{
  "id": "g1",
  "name": "Отпуск в Грузии",
  "target": 180000.0,
  "saved": 68000.0,
  "cur": "RUB",
  "hint": "Хочу поехать в мае"
}
```

## Долги (`debts`)

```json
{
  "id": 1042, "kind": "lent", "party": "Сапар", "principal": 1000.0, "expected": 1100.0,
  "cur": "TMT", "date": 20710, "due": 20740, "acc": "card", "txId": 1041,
  "payments": [{"id": 1050, "date": 20725, "amount": 400.0, "txId": 1049, "extraTxId": null}],
  "closed": false, "note": ""
}
```

- `kind` — `lent` (дали в долг) или `borrowed` (взяли).
- `principal` — тело долга, `expected` — сколько должно вернуться всего; разница
  между ними и есть заработок или переплата.
- `txId` — операция выдачи или получения в служебной категории `debt`: она меняет
  остаток счёта, но `Calc.isReal` её отсекает, поэтому в расходы и доходы она не идёт.
- В платеже `txId` — движение тела (та же служебная категория), `extraTxId` —
  настоящий доход в категории `debtGain` либо расход в `debtCost`, если платёж
  вышел за тело долга.
- Долг считается закрытым, когда `closed` или когда сумма платежей покрыла `expected`.

## Бизнес: прайс, клиенты, заказы

Появляются, когда включён модуль «Бизнес» (`settings.business`). У выключенного модуля
списки пустые, и старые копии открываются как есть.

```json
{
  "products": [
    {"id": "p1", "name": "Торт на заказ", "price": 171.0, "cost": 68.5, "unit": "шт", "archived": false}
  ],
  "customers": [
    {"id": "cl1", "name": "Айна", "contact": "Телефон", "note": ""}
  ],
  "orders": [
    {
      "id": 600, "no": "2026-008", "customerId": "cl1", "date": 20710, "due": null,
      "items": [{"productId": "p2", "name": "Капкейки, 12 шт", "qty": 1.0, "price": 83.9, "cost": 34.3}],
      "discount": 0.0, "extraCost": 0.0, "cur": "TMT", "status": "paid",
      "incomeTxId": 1001, "costTxId": null, "note": ""
    }
  ]
}
```

- `price` и `cost` в прайсе — **в основной валюте**, как лимиты категорий: при смене
  основной валюты они пересчитываются.
- В позиции заказа цена и затраты зафиксированы в **валюте заказа** (`cur`) на момент
  заказа: последующая правка прайса или курса их не трогает.
- `status` — строка: `new`, `work`, `done`, `paid`, `cancelled`. Незнакомое значение
  не ломает чтение — оно просто показывается как «новый».
- `incomeTxId` — операция дохода, созданная оплатой (категория `sale`); `costTxId` —
  операция расхода, если затраты списывали со счёта (категория `cost`). Удаление
  операции снимает с заказа отметку об оплате, удаление заказа удаляет его операции.
- Сумма заказа = Σ `qty × price` − `discount`; затраты = Σ `qty × cost` + `extraCost`.

## Регулярные платежи (`recurring`)

```json
{
  "id": "rec-phone", "title": "Рассрочка за телефон", "amount": 4500.0, "income": false,
  "accId": "card", "cat": "other", "every": "month", "start": 20560,
  "total": 12, "done": 5, "auto": false, "remindDays": 1, "remindedFor": 0,
  "by": "", "active": true, "changedAt": 0
}
```

- `amount` всегда положительная, направление — в `income`; сумма в валюте счёта.
- `every` — `week`, `month` или `year`; дата платежа номер *n* — `start` плюс *n* периодов.
- `total` — сколько платежей всего (рассрочка, кредит), `0` — бессрочно; `done` — сколько проведено.
- `auto` — записывать сразу; иначе платёж ждёт на экране «На проверку».
- Проводит платёж только автор (`by`): у двоих в общем бюджете записи одинаковые,
  и без этого каждый платёж появился бы дважды.

## Заявки на расход (`requests`)

Трата с общего счёта от `approveFrom` и выше становится заявкой: `status` — `pending`,
`approved`, `declined` или `cancelled`; `decidedBy`/`decidedAt` — кто и когда решил;
`txId` — операция, которую автор записал после одобрения.

## Общий бюджет (`space`, `deleted`)

`space` — общее пространство: идентификатор, участники со своими диапазонами номеров,
секрет для обмена и выбранные способы (`links`: Google Диск, WebDAV, Wi-Fi). `deleted` —
«надгробия» удалённых записей с временем удаления, чтобы удалённое не вернулось из снимка
второго участника. Подробности — в [SYNC.md](SYNC.md).

## Банковские СМС и черновики

- `smsSources` — правила: отправитель, счёт, последние 4 цифры карты (`cardMask`),
  слова расхода, прихода и пропуска, флаг «записывать сразу».
- `pushApps` — приложения, приславшие уведомления с суммами (Android).
- `merchantCats` — какую категорию человек выбрал для магазина, чтобы подставлять её дальше.
- `inbox` — черновики операций: источник (`photo`, `sms`, `push`, `qr`, `recurring`),
  предполагаемые дата, сумма, счёт и категория, исходный текст (`raw`).

## Настройки (`settings`)

| Поле | Что означает |
| --- | --- |
| `mainCur` | основная валюта: в ней считаются баланс, бюджеты и отчёты |
| `dark` | тёмная тема |
| `lang` | язык: `auto`, `ru`, `en`, `tk`, `uz`, `kk` |
| `rates` | банковские курсы: сколько единиц основной валюты стоит единица другой, `{"USD": 3.5}` |
| `marketRates` | рыночные курсы там, где они отличаются от банковских, `{"USD": 19.5}` |
| `rateMode` | по какому курсу считать итоги: `bank` или `market` |
| `ratesAt`, `ratesSource` | когда и откуда (`CBR`, `NBK`, `CBU`) последний раз подтянуты официальные курсы |
| `moneyAt` | когда меняли валюту и курсы — единственная часть настроек, общая для участников |
| `currencyCodes` | включённые валюты |
| `customCurrencies` | валюты, заведённые вручную: код, символ, название |
| `onboarded` | пройдена ли заставка первого запуска |
| `userName` | как обращаться к пользователю на главном экране |
| `remind`, `remindHour` | вечернее напоминание и час |
| `showKopecks` | показывать копейки в суммах |
| `allowNegative` | разрешить уводить счета в минус (без этого расход больше остатка не запишется) |
| `business` | включён ли раздел «Бизнес» |
| `autoBackup`, `lastBackupAt`, `driveLinked` | состояние резервного копирования |
| `aiProvider`, `aiModels`, `customEndpoint`, `yandexFolder`, `aiSets` | настройки ИИ-советника |
| `sms`, `bankPush` | чтение банковских СМС и уведомлений банковских приложений |

**API-ключей и паролей здесь нет.** Ключи ИИ и пароль WebDAV лежат в отдельном
хранилище — Android Keystore или iOS Keychain — и не попадают ни в файл данных,
ни в резервную копию.

## Обмен через CSV

Файл с колонками:

```
date;type;amount;currency;account;to_account;to_amount;category;note
2026-09-14;expense;-1200;TMT;Kart · 4417;;;Azyk;Bazar
2026-09-14;income;4500;TMT;Kart · 4417;;;Aýlyk;
2026-09-14;transfer;-500;TMT;Kart · 4417;Nagt pul;500;;
```

- `type` — `expense`, `income` или `transfer`. Взносы на цели выгружаются как `goal`
  и при загрузке пропускаются: ими управляет сама цель. Сколько строк пропущено,
  видно в предпросмотре.

Заказы выгружаются отдельным файлом с колонками
`no;date;customer;status;currency;total;cost;profit;items;note`; загрузки для них нет.
- Разделитель — точка с запятой или запятая (определяется по первой строке),
  кодировка UTF-8 с BOM, чтобы Excel открывал файл без плясок.
- Дата понимается в виде `2026-09-14`, `14.09.2026` или `14/09/2026`.
- Сумма расхода может быть и отрицательной, и положительной — знак ставится по типу строки.
- `to_amount` нужен только для переводов между разными валютами; если он пуст, сумма
  пересчитается по текущему курсу.
- Счета и категории ищутся по названию без учёта регистра. Чего нет — создаётся:
  счёт с нулевым остатком и валютой из строки, категория с автоматическим цветом.

Перед загрузкой приложение показывает, сколько строк подходит, сколько с ошибками
и что будет создано; сами данные меняются только после подтверждения.

## Совместимость

Чтение включает `ignoreUnknownKeys`, а все новые поля добавляются со значением по
умолчанию. Поэтому:

- копия, снятая старой версией, открывается новой — недостающие поля получают значения
  по умолчанию (так, например, добавились цвета категорий и список валют);
- копия из новой версии открывается старой — незнакомые поля просто игнорируются.

`version` отмечает формат: **1** — курсы и лимиты в рублях, **2** — в долларах,
**3** — в основной валюте пользователя (`settings.mainCur`), её собственный курс всегда 1.
Файл версии 1 или 2 (в том числе старая копия с Google Диска) переводится в версию 3 при
загрузке: все курсы делятся на прежний курс основной валюты, лимиты категорий пересчитываются
так же, а результат сразу сохраняется. Суммы операций и остатки счетов хранятся в валютах
самих счетов и не затрагиваются.

Смена основной валюты в настройках делает ровно тот же пересчёт: база переезжает на новую
валюту, относительные курсы сохраняются.

## Резервная копия

Файл в Google Диске называется `kopeechka-ГГГГ-ММ-ДД_ЧЧ-ММ-СС.json` и лежит в папке
«Копеечка — резервные копии». Хранятся 10 последних, старые удаляются автоматически.
Копию можно сохранить и **файлом** `kopeechka-backup-ГГГГ-ММ-ДД.json` — на телефон или
в мессенджер — и восстановить из файла на любом телефоне.
Перед восстановлением текущее состояние сохраняется на телефоне в `files/before-restore.json`.

В копию не попадают черновики `inbox` и `pushApps` (`AppData.forExport`): там может лежать
текст банковских сообщений. В общий бюджет, кроме того, не уходят правила СМС,
`merchantCats` и сам `space` (`AppData.forSync`).
