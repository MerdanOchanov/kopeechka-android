# Резервные копии в Google Диск

## Как это устроено

Копия — это файл `kopeechka-ГГГГ-ММ-ДД_ЧЧ-ММ-СС.json` со всем состоянием приложения.
Он кладётся в папку **«Копеечка — резервные копии»** на Диске самого пользователя;
хранятся 10 последних, старые удаляются. Никакого сервера у приложения нет.

Используется область доступа **`drive.file`**: приложение видит только те файлы,
которые само создало. Остальной Диск ему недоступен. Это «несекретная» область,
поэтому проверка приложения в Google не требуется.

Токен доступа на Android берётся через `Identity.getAuthorizationClient` (Google Play
services, `app/.../net/DriveBackup.kt`), дальше запросы идут в Drive REST v3 из общего
кода (`shared/.../net/DriveApi.kt`, Ktor). Тот же Диск служит одним из способов обмена
в общем бюджете — см. [SYNC.md](SYNC.md).

**API-ключи ИИ в копию не попадают** — они лежат отдельно, в Android Keystore / iOS Keychain.

Если Google недоступен, есть **копия файлом**: Настройки → Резервная копия →
«Сохранить» или «Отправить», восстановление — «Восстановить из файла».

## Настройка для себя

Google пускает приложение к Диску, только если оно зарегистрировано в Google Cloud:
сверяются **имя пакета** и **SHA-1 ключа подписи**. Client ID в код вставлять не нужно.

1. [console.cloud.google.com](https://console.cloud.google.com/) → создать проект.
2. **APIs & Services → Library** → **Google Drive API** → **Enable**.
3. **OAuth consent screen**: тип **External**, название, почта. В **Test users** добавить
   свой аккаунт — пока приложение в режиме Testing, входить могут только они (до 100 штук).
4. **Credentials → Create credentials → OAuth client ID → Android** — именно Android,
   а не Desktop app: приложение получает токен через Google Play services, а они сверяют
   имя пакета и отпечаток подписи, а не client_id. У клиента типа Android консоль
   не предлагает скачать JSON — это нормально, скачивать нечего, в коде client_id не нужен.
   Если по ошибке создать Desktop-клиент, диалог выбора аккаунта покажется, но после
   выбора Google молча откажет — это и есть код 10.
   - Package name — свой у каждого варианта сборки:

     | Вариант | Package name | SHA-1 |
     | --- | --- | --- |
     | `full` (APK с GitHub) | `app.kopeechka.finance` | отладочного ключа той машины, где собран APK |
     | `play` (Google Play) | `com.arassanusga.kopeechka` | ключа подписи Play App Signing: `DB:86:CA:0E:5D:55:5B:D8:9F:71:18:D4:51:96:55:A7:F2:82:E9:51` |

   - SHA-1 отладочного ключа:
     ```bash
     keytool -list -v -keystore %USERPROFILE%\.android\debug.keystore -alias androiddebugkey -storepass android -keypass android
     ```
5. В приложении: **Настройки → Резервная копия → «Подключить Диск и сохранить»**.

## Распространение на других людей

1. **Свой ключ подписи.** Отладочный не годится: он свой на каждой машине.
   Создайте release-keystore (см. [BUILD.md](BUILD.md)) и добавьте его SHA-1
   вторым Android-клиентом в Google Cloud.
   Для Google Play включается Play App Signing — тогда нужен SHA-1 из
   **Play Console → Setup → App integrity**, иначе вход сломается именно в версии из Play.
2. **Опубликовать экран согласия:** Google Auth Platform → **Publish app**,
   статус Testing → **In production**. Для области `drive.file` проверка Google не нужна.
3. **Документы:** для опубликованного экрана согласия нужны ссылки на политику
   конфиденциальности (и желательно условия использования). В политике достаточно честно
   описать: данные хранятся на устройстве, копии — в Диске самого пользователя,
   разработчик доступа к ним не имеет.
4. **Google Play (если пойдёте туда):** аккаунт разработчика, форма Data safety,
   возрастной рейтинг, сборка в формате AAB.

Если раздавать просто APK по ссылке — достаточно пунктов 1–3.

## Частые ошибки

| Симптом | Причина |
| --- | --- |
| Ошибка 10 / `DEVELOPER_ERROR` | не совпали имя пакета или SHA-1 ключа |
| 403 при сохранении | в проекте Google Cloud не включён Drive API |
| «Доступ истёк, подключите Диск заново» | истёк токен — нажмите подключение ещё раз |
| «Доступ заблокирован» при входе | аккаунт не добавлен в Test users, пока приложение в Testing |
| Диалог аккаунта появляется, но Диск не подключается | создан клиент типа Desktop вместо Android |
| Только что созданный клиент не работает | настройки Google расходятся от пяти минут до нескольких часов |

## Автоматическая копия

Переключатель «Автоматически раз в день» ставит периодическую задачу WorkManager
с условием Wi-Fi. Если Google потребует подтвердить вход заново, фоновая задача
тихо пропускает попытку — копия снимется, когда пользователь откроет приложение
и подключит Диск заново.
