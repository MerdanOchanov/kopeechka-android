# Архитектура

## Общая схема

```
Android: MainActivity ─┐                        ┌─ iOS: MainViewController (SwiftUI-обёртка)
                       ▼                        ▼
                 KopeechkaRoot (Compose Multiplatform, общий код)
                       │
                       ├── экраны: главная · операции · бюджет · отчёты · настройки
                       ├── страницы настроек: счета, категории, цели, долги, бизнес,
                       │   регулярные платежи, СМС, «Вместе», валюты, копии
                       └── оверлеи: операция, «На проверку», ИИ-советник, выписка, редакторы
                       │
                 AppViewModel ──> Storage (порт) ──> StateFlow<AppData>
                       │
                       ├── Calc            расчёты поверх AppData
                       ├── Sync            слияние общего бюджета
                       ├── SmsParse        разбор банковских СМС и уведомлений
                       ├── FiscalQr · Statement · Receipt   чеки и выписки
                       ├── Recurrings      регулярные платежи
                       └── net/            ИИ, Google Диск, WebDAV, Wi-Fi, курсы ЦБ, обновления
```

Почти весь код — общий, в модуле `:shared` (Kotlin Multiplatform + Compose
Multiplatform). Платформы подключаются через интерфейсы в `Ports.kt`:

| Порт | Android (`app/`) | iOS (`shared/src/iosMain`) |
| --- | --- | --- |
| `Storage` — файл данных | `data/Store.kt`, `AtomicFile` | `IosStorage.kt` |
| `SecretStore` — ключи ИИ, пароль WebDAV | `data/SecureStore.kt`, Android Keystore | `IosSecrets.kt`, Keychain |
| `Platform` — файлы, камера, QR, напоминания, вход в Google, СМС, уведомления, Wi-Fi-обмен | `AndroidPlatform.kt` | `IosPlatform.kt`, `IosImagePicker.kt`, `IosFiles.kt` |

Экраны о платформе не знают: если возможности нет (СМС на iOS, чтение уведомлений
в iOS), `Platform` честно отвечает `canReadSms = false`, и пункт просто не показывается.

## Данные

Всё состояние — один неизменяемый объект `AppData`: счета, категории, операции,
цели, долги, заказы, регулярные платежи, заявки, правила СМС, черновики и настройки.
Он лежит в одном JSON-файле и раздаётся интерфейсу через `StateFlow`. Поле за полем —
в [DATA_MODEL.md](DATA_MODEL.md).

**Почему не база данных.** Личные финансы — это тысячи операций, сотни килобайт.
Один файл даёт три преимущества: резервная копия совпадает с форматом хранения,
нет миграций схемы (новые поля получают значения по умолчанию, `ignoreUnknownKeys`
терпит старые), и всё состояние доступно синхронно.

Запись атомарная: временный файл подменяет основной, поэтому прерывание на середине
не портит данные. Каждое изменение идёт через `Storage.update`, который заодно ставит
отметку `changedAt` изменённым записям (`Sync.stamp`) — на ней держится слияние.

### Балансы считаются, а не хранятся

У счёта есть только `initial` — стартовый остаток. Текущий баланс выводится:

```
balance(счёт) = initial + Σ (суммы операций по счёту) + Σ (зачисления переводов)
```

Редактирование и удаление операции автоматически исправляют баланс — нет состояния,
которое могло бы разойтись с историей.

### Служебные операции

Переводы, взносы на цель и движение тела долга — обычные операции со служебными
категориями (`transfer`, `goal`, `debt`). `Calc.isReal()` отсекает их из доходов
и расходов, чтобы перекладывание денег между своими счетами не выглядело тратой.

## Расчёты (`Calc`)

`Calc` — обёртка над `AppData` с датой «сегодня». Создаётся на каждую отрисовку,
тяжёлые агрегаты — `by lazy`. Отвечает за:

- **валюты**: база курсов — основная валюта пользователя (её курс всегда 1).
  У валюты два курса — банковский (`rates`) и рыночный (`marketRates`); итог
  считается по выбранному режиму, а где рыночного нет — по банковскому.
  Золото — «валюта» `XAU` в граммах с ценой грамма вместо курса;
- балансы, месячные бюджеты, «можно тратить в день»;
- периоды отчётов `range(period, offset)`, разрезы `breakdown()`, столбики `series()`,
  сравнение `compare()` с тем же отрезком прошлого периода;
- долги, бизнес (выручка, затраты, маржа), цвета категорий.

## Автоматический ввод

Всё, о чём приложение догадалось само, сначала становится **черновиком**
(`InboxItem`) и ждёт подтверждения на экране «На проверку»:

| Источник | Где разбирается | Особенности |
| --- | --- | --- |
| СМС банка | `SmsParse` (Android: `SmsReceiver`) | правило по отправителю и цифрам карты; знак суммы важнее слов; сумма без валюты ищется после ключевого слова |
| Уведомление банковского приложения | тот же `SmsParse` (`BankNotificationListener`) | запоминаются приложения, приславшие суммы |
| QR-код фискального чека | `FiscalQr` | без сети: `t=…&s=…&n=…` |
| Фото чека | `Ai` + `Receipt.parse` | модель возвращает строгий JSON |
| Выписка CSV | `Statement` | колонки угадываются по заголовкам, дубли отсекаются |
| Регулярный платёж | `Recurrings.due` | проводит только автор записи, чтобы в общем бюджете платёж не удвоился |

Правило с флагом «записывать сразу» минует черновик. Выбранная для магазина категория
запоминается в `merchantCats`.

## Общий бюджет

Каждый участник пишет свой снимок (`SyncSnapshot`) в общее место и читает чужие;
`Sync.merge` сливает их по принципу «последняя правка побеждает», удалённое помнится
в `deleted`. Идентификаторы не пересекаются: у каждого участника свой диапазон
(`Sync.slotStart`). Транспорты (`net/SyncTransport.kt`): Google Диск, WebDAV и прямой
обмен по Wi-Fi (Android поднимает сервер Ktor CIO на портах 8733–8735, доступ по коду).
Подробно — в [SYNC.md](SYNC.md).

## Интерфейс

Compose Multiplatform без навигационной библиотеки: экран — это поле `tab`/`page`
во ViewModel, оверлеи — nullable-поля (`draft`, `accEdit`, `inboxEdit` …). Кнопка «назад»
обрабатывается одним методом `AppViewModel.back()`, который закрывает верхний слой.

Оформление — дизайн-система Industry (`ui/theme`): токены светлой и тёмной темы через
`CompositionLocal`, квадратные углы, волосяные рамки, метки «+» по углам. Шрифты Barlow
и Barlow Condensed; кириллицу на Android подхватывает системный узкий шрифт через
`Typeface.CustomFallbackBuilder`.

## Языки

Пять языков — русский, английский, туркменский, узбекский (латиница) и казахский —
лежат картами «ключ → строка» в `data/Lang*.kt`, а не в ресурсах платформы: язык
переключается внутри приложения и меняет не только интерфейс, но и данные — названия
валют, месяцы, разделители чисел, запрос к ИИ и демо-данные.

- `Lang.t("key", arg)` подставляет `{0}`, `{1}`; `Lang.pl(n, "day")` выбирает форму
  множественного числа (в русском три, в английском две, в тюркских языках одна).
- Пропущенный ключ откатывается по цепочке: `tk → en → ru`, `uz → ru`, `kk → ru`.
- В Compose язык раздаётся через `LocalLang` (`T.l`), вне Compose — `AppViewModel.l`,
  `Calc.l`, `Currencies.lang`.

## Сеть

Все запросы — Ktor из общего кода (`net/Http.kt`; движок OkHttp на Android, Darwin на iOS).

| Модуль | Куда | Когда |
| --- | --- | --- |
| `Ai.kt` | Anthropic, OpenAI, Google, Сбер (GigaChat), Yandex Cloud, свой endpoint | вопрос советнику или фото чека, по ключу пользователя |
| `DriveApi.kt` | Google Drive REST v3, область `drive.file` | копии и «Вместе» через Диск |
| `SyncTransport.kt` | WebDAV-сервер пользователя, второй телефон в сети | обмен в «Вместе» |
| `BankRates.kt` | cbr.ru, nationalbank.kz, cbu.uz | по кнопке «Официальные курсы» |
| `Updates.kt` | api.github.com | проверка новой версии, только сборка с GitHub |

Для GigaChat на Android добавлен `network_security_config`: доменам Сбера разрешено
доверять сертификатам, установленным пользователем (корневой сертификат Минцифры).

## Фон (Android)

`work/Workers.kt` — WorkManager: ежедневная копия в Диск по Wi-Fi, вечернее напоминание,
проведение регулярных платежей и напоминания о них.

## Что намеренно не сделано

- Нет DI-фреймворка: зависимости создаются в `Application` и передаются вручную.
- Нет репозиториев и use-case'ов поверх `Storage` — на таком объёме это лишний слой.
- Нет своего сервера: всё, что уходит в сеть, уходит туда, куда выбрал пользователь.
