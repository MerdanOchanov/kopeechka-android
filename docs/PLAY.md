# Публикация в Google Play

## Два варианта приложения

| Вариант | Пакет | Для чего | Чем отличается |
| --- | --- | --- | --- |
| `full` | `app.kopeechka.finance` | APK на GitHub, отладка на своём телефоне | все функции, включая чтение банковских СМС и проверку обновлений с GitHub |
| `play` | `com.arassanusga.kopeechka` | Google Play | без чтения СМС (нет ни разрешений, ни приёмника, ни пункта в настройках) и без проверки обновлений — их доставляет Play |

Почему `play` пока без автоматического чтения СМС. Разрешения `READ_SMS`
и `RECEIVE_SMS` Google Play пропускает только после одобренной **декларации
разрешений**. Без неё выпуск с такими разрешениями не пройдёт проверку даже во
внутреннем тестировании. До одобрения в варианте `play` работает **вставка СМС
вручную** (Настройки → Банковские сообщения): правило подбирается по тексту,
дата берётся из сообщения.

### Как включить чтение СМС в Play

1. Поставить `SMS_ENABLED = true` у варианта `play` в `app/build.gradle.kts`
   и удалить `app/src/play/AndroidManifest.xml`. Экран разрешений первого запуска
   сам начнёт спрашивать доступ к СМС с объяснением — Google этого требует.
2. Поднять `versionCode`, собрать AAB и загрузить во **внутреннее тестирование**.
   Play Console остановит выпуск и откроет **Контент приложения → Декларация
   разрешений** (Permissions declaration form).
3. Заполнить декларацию текстом ниже, приложить видео и отправить.
   Проверка — обычно несколько дней.
4. После одобрения опубликовать выпуск.

### Текст декларации

**Основная функция приложения:** «Учёт финансов и бюджета» — категория исключения
*SMS-based money management* (приложения, которые помогают отслеживать и вести
бюджет по банковским сообщениям).

**Как приложение использует разрешения (EN, в форму):**

```
Kopeechka is a personal finance and budgeting app. Its core feature is automatic
expense tracking from bank SMS: when the user's bank sends a transaction SMS
(purchase, cash withdrawal, top-up), the app reads the amount, card digits and
merchant and turns it into a draft transaction that the user confirms.

RECEIVE_SMS is used to process new bank transaction messages as they arrive.
READ_SMS is used once, when the user enables the feature, to import the last
90 days of bank messages so the budget is complete from day one.

Only messages from senders the user explicitly added as bank rules are processed.
All parsing happens on the device; message text is never uploaded, never included
in backups and never shared. The feature is off by default: the user turns it on
in Settings, sees an explanation screen, and then the system permission dialog.
Without the permission the app still works and offers manual paste of bank SMS.
Many banks in Turkmenistan and other CIS countries send transaction details only
by SMS, with no API or banking-app notifications, so SMS is the only way to track
spending automatically.
```

**Видео (обязательно):** 30–60 секунд записи экрана, ссылка на YouTube (можно
«доступ по ссылке»): Настройки → Ввод без рук → включить «Читать СМС банков» →
экран объяснения → системное окно разрешения → правило банка → пришедшая СМС →
черновик в «На проверку» → «Записать».

**Политика конфиденциальности** — [PRIVACY.md](PRIVACY.md), раздел про СМС уже есть.

Разница задаётся флагами `BuildConfig.SMS_ENABLED` и `UPDATES_FROM_GITHUB`, а манифест
варианта `play` вычёркивает разрешения и приёмник через `tools:node="remove"`.

**Уведомления банков** в варианте `play` остаются: служба `BankNotificationListener`
работает только после того, как человек сам включит доступ к уведомлениям в системных
настройках. Отдельной декларации для этого Play не требует, но функция должна быть
описана в политике конфиденциальности и в анкете безопасности данных — она там есть.

## Сборка для Play

```bash
gradlew.bat :app:bundlePlayRelease
```

Файл: `app/build/outputs/bundle/playRelease/app-play-release.aab`.

Пакет подписывается **ключом загрузки**. Его настройки — в `keystore.properties`
в корне проекта (в `.gitignore`):

```
storeFile=C:/Users/<вы>/kopeechka-keys/kopeechka-upload.jks
storePassword=…
keyAlias=kopeechka-upload
keyPassword=…
```

Без этого файла всё остальное собирается как обычно, а релиз просто остаётся
неподписанным.

**Сохраните ключ.** Скопируйте папку `kopeechka-keys` вместе с `keystore.properties`
туда, где она не потеряется: в менеджер паролей или на зашифрованный носитель.
Если ключ загрузки всё же пропадёт, при включённом Play App Signing его можно
заменить через поддержку Google Play, но это займёт дни.

Отпечатки текущего ключа загрузки:

```
SHA-1:   E1:51:1C:05:92:C3:72:86:95:38:02:CC:46:99:5A:D2:00:A8:45:65
SHA-256: 10:E1:89:9F:70:1D:CF:70:44:51:5D:6F:EC:8E:D7:9C:EA:2B:B2:B8:14:38:AE:8B:A9:6A:73:23:72:4B:5A:6B
```

## Номер версии

`versionCode` в `app/build.gradle.kts` должен расти с каждой загрузкой в Play —
тот же номер второй раз не примут. `versionName` видят люди. Сейчас: **1.8 (11)**;
сборка 10 уже загружалась в Play, поэтому следующий выпуск — только с 11 и выше.

## Чек-лист закрытого тестирования

1. **Play App Signing** — оставить включённым (по умолчанию). Google хранит ключ
   подписи приложения, мы — только ключ загрузки.
2. **Выпуск** → Закрытое тестирование → создать трек → загрузить AAB.
3. **Что нового** — текст ниже.
4. **Тестировщики** — список адресов Google или группа Google.
5. **Политика конфиденциальности** — ссылка на [PRIVACY.md](PRIVACY.md):
   `https://github.com/MerdanOchanov/kopeechka-android/blob/main/docs/PRIVACY.md`
6. **Безопасность данных** — см. ниже.
7. **Google Диск.** После первой загрузки в Play Console → Настройка → Целостность
   приложения появится **SHA-1 ключа подписи приложения**. Его нужно добавить ещё
   одним Android-клиентом OAuth в Google Cloud, иначе у тех, кто поставил приложение
   из Play, резервные копии и «Вместе» через Google Диск не авторизуются.
   **Уже сделано:** пакет `com.arassanusga.kopeechka`,
   SHA-1 `DB:86:CA:0E:5D:55:5B:D8:9F:71:18:D4:51:96:55:A7:F2:82:E9:51`,
   экран согласия опубликован. См. [GOOGLE_DRIVE.md](GOOGLE_DRIVE.md).

### Безопасность данных — ответы для анкеты

- **Собирает ли приложение данные или передаёт их третьим лицам?** Приложение
  передаёт данные только по действию пользователя: в его собственный Google Диск,
  его WebDAV-сервер, второму участнику общего бюджета и ИИ-провайдеру по ключу
  пользователя. Разработчик данных не получает.
- **Финансовая информация** (история покупок / прочая финансовая информация) —
  передаётся, только когда пользователь включает резервные копии, общий бюджет или
  ИИ-советник. Необязательно, по выбору пользователя.
- **Фотографии** — снимок чека передаётся ИИ-провайдеру, только когда пользователь
  сам распознаёт чек. QR-код чека разбирается на телефоне и никуда не уходит. Необязательно.
- **Уведомления банковских приложений** — читаются на телефоне, если пользователь сам
  дал доступ; текст никуда не передаётся и в копии не попадает. В анкете это не
  «сбор», так как данные не покидают устройство.
- **Курсы валют** — запрос к сайту центрального банка по кнопке; личных данных в нём нет.
- **Шифрование при передаче** — да, облачные запросы идут по HTTPS. Исключение —
  обмен «Рядом по Wi-Fi» внутри локальной сети; если это важно для анкеты,
  отвечайте осторожно и опирайтесь на PRIVACY.md.
- **Удаление данных** — все данные удаляются вместе с приложением.

Окончательные формулировки выбирает владелец аккаунта разработчика: анкета —
юридическое заявление перед Google.

## Установка поверх сборки с GitHub

Сборка из Play подписана другим ключом, поэтому **поверх APK с GitHub она не
встанет** — Android потребует удалить старое приложение, а вместе с ним и данные.
Перед переходом сохраните данные: резервная копия в Google Диск или выгрузка CSV.
