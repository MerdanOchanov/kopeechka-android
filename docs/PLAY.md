# Публикация в Google Play

## Два варианта приложения

| Вариант | Для чего | Чем отличается |
| --- | --- | --- |
| `full` | APK на GitHub, отладка на своём телефоне | все функции, включая чтение банковских СМС |
| `play` | Google Play | без чтения СМС: нет ни разрешений, ни приёмника, ни раздела в настройках |

Почему `play` без СМС. Разрешения `READ_SMS` и `RECEIVE_SMS` Google Play пропускает
только после одобренной **декларации разрешений** (Policy → App content →
Sensitive permissions). Без неё выпуск с такими разрешениями не пройдёт проверку
даже в закрытом тестировании. Если декларацию подадите и её одобрят, достаточно
убрать `app/src/play/AndroidManifest.xml` и поставить `SMS_ENABLED = true`
у варианта `play` в `app/build.gradle.kts`.

Разница задаётся флагом `BuildConfig.SMS_ENABLED`, а манифест варианта `play`
вычёркивает разрешения и приёмник через `tools:node="remove"`.

## Сборка для Play

```bash
gradlew.bat :app:bundlePlayRelease
```

Файл: `app/build/outputs/bundle/playRelease/app-play-release.aab`.

Пакет подписывается **ключом загрузки**. Его настройки — в `keystore.properties`
в корне проекта (в `.gitignore`):

```
storeFile=C:/Users/<вы>/kopeechka-keys/kopeechka-upload.jks
storePassword=…
keyAlias=kopeechka-upload
keyPassword=…
```

Без этого файла всё остальное собирается как обычно, а релиз просто остаётся
неподписанным.

**Сохраните ключ.** Скопируйте папку `kopeechka-keys` вместе с `keystore.properties`
туда, где она не потеряется: в менеджер паролей или на зашифрованный носитель.
Если ключ загрузки всё же пропадёт, при включённом Play App Signing его можно
заменить через поддержку Google Play, но это займёт дни.

Отпечатки текущего ключа загрузки:

```
SHA-1:   E1:51:1C:05:92:C3:72:86:95:38:02:CC:46:99:5A:D2:00:A8:45:65
SHA-256: 10:E1:89:9F:70:1D:CF:70:44:51:5D:6F:EC:8E:D7:9C:EA:2B:B2:B8:14:38:AE:8B:A9:6A:73:23:72:4B:5A:6B
```

## Номер версии

`versionCode` в `app/build.gradle.kts` должен расти с каждой загрузкой в Play —
тот же номер второй раз не примут. `versionName` видят люди.

## Чек-лист закрытого тестирования

1. **Play App Signing** — оставить включённым (по умолчанию). Google хранит ключ
   подписи приложения, мы — только ключ загрузки.
2. **Выпуск** → Закрытое тестирование → создать трек → загрузить AAB.
3. **Что нового** — текст ниже.
4. **Тестировщики** — список адресов Google или группа Google.
5. **Политика конфиденциальности** — ссылка на [PRIVACY.md](PRIVACY.md):
   `https://github.com/MerdanOchanov/kopeechka-android/blob/main/docs/PRIVACY.md`
6. **Безопасность данных** — см. ниже.
7. **Google Диск.** После первой загрузки в Play Console → Настройка → Целостность
   приложения появится **SHA-1 ключа подписи приложения**. Его нужно добавить ещё
   одним Android-клиентом OAuth в Google Cloud (пакет `app.kopeechka.finance`),
   иначе у тех, кто поставил приложение из Play, резервные копии и «Вместе» через
   Google Диск не авторизуются. См. [GOOGLE_DRIVE.md](GOOGLE_DRIVE.md).

### Безопасность данных — ответы для анкеты

- **Собирает ли приложение данные или передаёт их третьим лицам?** Приложение
  передаёт данные только по действию пользователя: в его собственный Google Диск,
  его WebDAV-сервер, второму участнику общего бюджета и ИИ-провайдеру по ключу
  пользователя. Разработчик данных не получает.
- **Финансовая информация** (история покупок / прочая финансовая информация) —
  передаётся, только когда пользователь включает резервные копии, общий бюджет или
  ИИ-советник. Необязательно, по выбору пользователя.
- **Фотографии** — снимок чека передаётся ИИ-провайдеру, только когда пользователь
  сам распознаёт чек. Необязательно.
- **Шифрование при передаче** — да, облачные запросы идут по HTTPS. Исключение —
  обмен «Рядом по Wi-Fi» внутри локальной сети; если это важно для анкеты,
  отвечайте осторожно и опирайтесь на PRIVACY.md.
- **Удаление данных** — все данные удаляются вместе с приложением.

Окончательные формулировки выбирает владелец аккаунта разработчика: анкета —
юридическое заявление перед Google.

## Установка поверх сборки с GitHub

Сборка из Play подписана другим ключом, поэтому **поверх APK с GitHub она не
встанет** — Android потребует удалить старое приложение, а вместе с ним и данные.
Перед переходом сохраните данные: резервная копия в Google Диск или выгрузка CSV.
